# 主题设计规范

> 版本 1 · 2026-10-13 · 适用于 DeskWidgets 的全部主题（目前：毛玻璃 Glass、像素 Pixel）。
> 新增主题、修改主题、给小组件做新画法之前，先读完这份文档。规范和代码不一致时：**先改规范，再改代码**。

用词约定：

- **必须**：硬性规定。违反会出 bug，或推翻用户已经确认过的决定（见附录 B）。
- **应该**：默认做法。有充分理由才能例外，例外要写进文末的「变更记录」。
- **可以**：自由发挥。

---

## 1. 什么是主题

主题 = 所有小组件共用的一整套外观：**卡片**（形状、材质、边缘）、**配色**（浅色、深色各一套）、**字体**、**图标**、**动效**。

主题**不决定**：小组件显示哪些信息、卡片尺寸和位置、怎么操作、文案。这些在所有主题里都一样（第 2 节）。

| 主题 | 枚举值 | 一句话 | 实现方式 |
|---|---|---|---|
| 毛玻璃 | `WidgetTheme.Glass`（默认） | 仿 Apple 小组件：实时模糊的薄玻璃，22 DIP 圆角，没有描边和阴影 | 组件的 XAML 内容 + `GlassBackdrop`（DWM host backdrop）+ `WidgetFrame` 的底色和高光层 |
| 像素 | `WidgetTheme.Pixel` | 不透明的像素画卡片，低分辨率逐像素绘制，整数倍放大，边缘永远是硬的 | 每个组件一个静态 `XxxPixelScene`，画在 `PixelCanvas` 上，由 `PixelSurface` 1:1 显示 |

切换入口：托盘菜单或任意小组件的右键菜单 →「Theme / 主题」。设置保存在 `settings.json` 的 `Theme` 字段。

---

## 2. 所有主题都必须遵守的规则

### 2.1 全局切换

- **必须**：主题是全局的，所有小组件一起切换，不支持一部分组件用毛玻璃、另一部分用像素。
- **必须**：切换立即生效，不用重启。宿主（`WidgetHost.SetTheme` → `WidgetWindow.ApplyTheme`）会用新主题重新创建每个组件。一个组件实例的 `WidgetContext.Theme` 在它的生命周期里不会变，所以组件自己不用处理主题切换。

### 2.2 尺寸与位置

- **必须**：每个尺寸的卡片占地固定：小 164×164、中 344×164、大 344×364（单位 DIP；中 = 两个小卡片加 16 DIP 间隔；大 = 两个中号上下叠起来，中间隔 36 DIP，也就是 Windows 默认图标间距下桌面网格在它们之间留的空隙，所以大号放在叠起来的一对旁边时，上下边缘是齐的）。桌面网格吸附和已保存的位置都依赖这些尺寸，换主题不能打乱用户的桌面。大号仍然占和以前一样的四行图标格，卡片加载时会重新吸附。
- **已知取舍**：关掉「对齐桌面网格」时，卡片之间保持 16 DIP 的间隔（`SnapToEdges`），所以那时大号比叠起来的两个中号高 20 DIP。
- **可以**：整数倍放大带来的少量偏差（像素主题在 125%、175% 缩放下比毛玻璃略大）。
- **必须**：内容画在卡片里面。窗口就是卡片，画到外面会被裁掉。
- **必须**：不为某个主题新增专属尺寸。
- **程序坞**（上面占地规则的例外，见 2.11）：程序坞不在桌面网格上，也没有自己的尺寸。它位于屏幕底边，默认居中，用户拖动过的就停在拖到的位置；长度随应用数量变化。小、中、大指的是图标尺寸：毛玻璃为 40、48、64 DIP；像素为 20、24、32 个美术像素（同样是 40、48、64 DIP）。所有尺寸的内边距和间距都是 12 DIP（6 个美术像素）。栏高分别为 64、72、88 DIP，栏的底边离屏幕底边 8 DIP（4 个美术像素）。每个屏幕只有一个程序坞。桌面图标整理器会把程序坞占的区域算进去，所以桌面图标不会压在它下面。

### 2.3 信息底线

主题可以换表现形式（圆环 ↔ 电池条、城市全名 ↔ 三字母代码），放得下时也可以多显示一点，但每个尺寸**不能少于**下表的内容：

| 组件 | 小 | 中 | 大 |
|---|---|---|---|
| 电池 | 单设备：图标、电量数字、充电状态，开启「显示设备名称」时加名称<br>多设备：2×2，每格是图标 + 电量（图形或数字）+ 充电状态 | 最多 4 个设备：图标、电量（图形 + 数字）、充电状态、名称（可关闭） | 最多 6 行：图标、名称、连接方式和状态、电量数字 |
| 时钟 | 星期、时间、日期 | 同小号 | 不支持 |
| 世界时钟 | 4 个表盘 + 城市标识（全名或三字母代码） | 4 个表盘，各带城市名、时间、当地日期 | 每城一行：表盘、城市名、与本地的时差（含今天/昨天/明天）、时间、当地日期 |
| 大文件夹 | 带文件夹名和项目数的标题；2×2 个格子 | 同样的标题；4×2 个格子 | 同样的标题；4×4 个格子 |
| 程序坞 | 每个应用都是 40 DIP 图标（像素为 20 个美术像素） | 每个应用都是 48 DIP 图标（像素为 24 个美术像素） | 每个应用都是 64 DIP 图标（像素为 32 个美术像素） |

- 没有设备时显示空状态文案（`Strings.NoDevices`）。
- 开启「显示未连接的设备」时，未连接的设备要明显变暗，电量用「—」代替。
- 右键菜单里的选项（显示设备名称、显示秒针、更换城市……）在所有主题里效果相同。
- 大文件夹：
  - 每个格子是该项的图标加名称：小、中号一行，大号最多两行（和面板一样的断行，`NameShortener.TwoLines`；放得下的名称仍是一行，靠上对齐；像素主题的宋体度量组在大号上仍是一行，因为四行放不下两行名称）。项目比格子多时，最后一格变成堆叠：下面几项的四个小图标加「+K」，K = 项目数 − (格子数 − 1)。刚好 4、8 或 16 项时没有堆叠。项目按文件夹的排序方式排列（最新、名称、类型或手动）。
  - 状态：空（「将文件拖到这里」）；找不到文件夹（「找不到文件夹」：标题不可点击，拒绝放入文件）；拖入悬停（一层色调和一个说明放下后会怎样的标签：移动到、复制到、在其中创建快捷方式，混合拖入时是「添加到」）。
  - 点击某一项会打开它；点击标题或堆叠会打开面板。面板里单击选中（Ctrl 和 Shift 扩展选择），双击或回车打开，随处打字就是搜索，第一次 Esc 清空搜索、第二次关闭面板，底部显示路径和「已选择 n 项」。选中的项目可以拖出去。**用户在面板里操作时，面板一直开着**（重命名、移到回收站、放回原处、排序、搜索、选择、项目菜单、卡片菜单里的「重命名文件夹…」、属性、往卡片上拖放、拖出），**这些操作弹出的窗口也不会让它关闭**，无论是我们的还是资源管理器的：对话框、文件操作的进度或冲突窗口、UAC 提示。**用户离开它时才关闭：** Esc（搜索框里有字时按第二次）、再次点击卡片的标题或堆叠、按下其他任何卡片、点击桌面或别的程序的窗口、切换到别的程序（Alt+Tab、任务栏）。**打开了什么之后也会关闭：** 双击、回车、打开、以管理员身份运行、在资源管理器中显示、打开文件所在位置。重命名后，改名的那一项被选中；移除之后，被移除项后面的那一项被选中。
  - 放不下的名称由同一个共享函数 `NameShortener` 缩短，按主题自己的字体量宽度（2.9）。
  - **搜索**（两个面板共用一个匹配函数，`Search/NameSearch.cs`；第 13 阶段，2026-10-24）：名称里含有输入的文字（不分大小写）就算匹配；输入只有拉丁字母和数字、名称里有中文时，如果输入拼出了名称里连续几个字的拼音**首字母**（"bz" 找到 壁纸，"qqyy" 找到 QQ音乐，可以跨过空格和 "&"）或者**整个音节（最后一个可以只写一部分）**（"bizhi"、"biz"），也算匹配。多音字（行、乐）任一读音都算。拼音表由 `tools/Make-PinyinTable.ps1` 从 Unicode 汉字数据库生成（Unicode License v3，许可声明放在 exe 旁）。
  - **显示更多选项**（项目菜单的最后一行，两个主题和卡片菜单里都有；第 13 阶段，2026-10-24）：通过 `IContextMenu` 打开 Windows 自己的右键菜单，对这个项目或选中的几个项目（打开方式、发送到、压缩、各个应用自己的条目）。**两个主题里都是 Windows 的菜单**，由系统绘制，和毛玻璃的消息框一样，像素主题改不了它的样子。菜单里的打开、重命名和删除用我们自己的代码（回收站、来源记录、原地重命名）；粘贴不显示。菜单出现期间和它启动的命令运行期间，面板保持打开。**风险：** 菜单条目来自在我们进程里运行的 shell 扩展（和缩略图处理程序一样）；慢的扩展会在菜单生成时卡住界面线程（装了十几个扩展时约 0.3 到 1.2 秒），扩展里的崩溃捕获不了。
  - 新卡片的文件夹建在哪里：用户选过**默认位置**的话就建在那里（卡片菜单里的「新文件夹的默认位置…」，保存为顶层设置 `FolderRoot`；文件夹不存在时会创建），否则建在用户目录下、桌面所在的盘上。「更换文件夹…」仍然可以让某一张卡片指向任何文件夹。

- 程序坞（一行，图标尺寸由用户选择）：
  - 每个应用都要显示，尺寸与所选图标尺寸一致；鼠标悬停时，栏上方显示它的名称。
  - **分组**（2026-11-03）：一个分组是栏上的一个图标，尺寸与栏的图标尺寸一致，里面有两个以上的程序；只剩一个程序的分组会变成那个程序，分组不能放进另一个分组里。分组的图标用前四个成员的小图排成 2 × 2，改名之前叫「分组」。图标的画法见 4.1 和 4.2，分组面板和菜单见 2.7。分组面板里的成员在任何栏尺寸下都以 48 DIP 绘制（像素为 24 个美术像素）。
  - 状态：空闲；悬停（图标上浮，并显示名称）；按下；缺失（应用找不到了：图标变暗，点击时可以把它移除）；运行中、打开中和关闭中（见下）。运行中的应用显示它的运行图标，没有小圆点，打开和关闭时都有动画。
    - **运行中**：程序在任务栏上有窗口。窗口按它的 AppUserModelID 匹配，其次是进程的 AppUserModelID，再其次是 exe 路径（有自定义图标的应用，还会按图标使用的启动器表匹配），从不按标题匹配。只在托盘里的程序不算运行中。只有一个网址的链接（例如 Steam 链接）没有运行状态。
    - **点击**：点击运行中的程序，会把它最前面的窗口拿到前面，窗口已最小化的话先还原。如果这个窗口已经在最前面：程序只有一个窗口时，点击会把它最小化；有多个窗口时，点击会按窗口句柄的固定顺序把下一个窗口拿到前面。按中键或按住 Shift 再点击，则启动另一个副本。
    - **打开中**：程序坞启动的程序会立即进入打开中的状态，一直保持到它的第一个窗口出现，或者等满 10 秒；然后回到空闲，这不是错误。启动失败也会立即回到空闲。每次启动时，点击那一刻都会先确认程序还在：缺失的程序会标为缺失，已经回来的程序则会启动。程序处于打开中时再点一下没有效果（否则只会再启动一份）；中键点击或 Shift+点击仍然可以。
    - **组成分组和用应用打开**：一个应用在另一个应用上停留 500 ms 后，松手就会组成分组；不是程序的文件拖到栏上时，会点亮能打开它们的应用，指针下的那个显示「用 {name} 打开」（见 2.7；画法见 4.1 和 4.2）。
  - 空状态：栏中间显示「把应用拖到这里」。

### 2.4 颜色的含义

主题决定具体色值，但**不能改变含义**：

- 电量 ≤ 20% 且没在充电：红；省电模式：黄；其他：绿（和 iOS 一致）。
- 充电中：显示闪电标志。
- 世界时钟：当地 6:00–18:00 用白天表盘，其余时间用夜间表盘；秒针用橙色强调色。
- 时钟的星期用强调色（红或橙）。

每个主题的具体色值见第 8 节。

### 2.5 语言与文字

- **必须**：所有可见文字取自 `Strings`（English 默认 + 中文），不在组件里硬写文案。日期用 `Strings.Culture` 或明确的格式串。
- **必须**：城市名在两种语言下都用英文（用户决定）。
- **必须**：时间用 24 小时制 `HH:mm`。
- **必须**：字体要么能覆盖中英文，要么有回退方案，而且**同一串文字不能混用两种字号**（像素主题的做法：像素字体拼不出来的文字，整串改用同一种点阵字体：宋体 12px 点阵，大文件夹里则是能覆盖整串文字的 Fusion Pixel 8px）。
- **必须**：两种语言都要放得下。英文通常更宽，中文通常更高（像素主题里中文行高 12px，像素字体只有 5px 或 7px）。实在放不下时可以换更紧凑的写法（例：像素主题的中文日期写成「10/13」而不是「10月13日」），并记到第 4 节。

### 2.6 跟随系统

- **必须**：提供浅色、深色两套配色，系统切换时立即重绘。XAML 内容监听 `ActualThemeChanged`；`PixelSurface` 会自动重绘。
- **必须**：在 100%–200% 缩放和跨显示器 DPI 变化时都保持清晰。
- **应该**：用到透明效果的主题，要说明 Windows 关闭「透明效果」或开启节电模式时的样子（毛玻璃会变成纯色，属于正常现象）。

### 2.7 操作与可读性

- **必须**：整张卡片都能拖动，内容不能拦截指针事件。卡片里不放按钮、输入框、滚动区域；设置一律放进右键菜单。
  - **例外（2026-10-21 批准，仅限大文件夹）：** 大文件夹的格子和标题接受点击：按下和松开都在系统的拖动阈值之内。按下后移动得更远，不论从哪里开始，仍然是拖动卡片。大文件夹卡片还接受拖入的文件。它仍然没有按钮、输入框和滚动区域：搜索、选择、排序和重命名都在面板里，面板是一个单独的窗口。
- **程序坞**（2026-10-31；程序坞里放的是应用而不是卡片，所以是上面卡片规则的例外）：程序坞里的应用接受点击，程序坞也接受拖入。点击应用会启动它；运行中的应用则把它的窗口拿到前面，或将其最小化（见 2.3）；点击分组会打开或关闭它的分组面板。从应用上开始的拖动会调整它的顺序；把一个应用拖到另一个应用上停留 500 ms 再松手，就会组成分组（见 2.3）。从栏的两端开始的拖动会移动整个栏，可以沿底边移动，也可以移到另一个屏幕的底边。
- **程序坞，拖入**：拖到栏上的程序会被添加，不会用它来打开文件；拖到一个分组上，它会加入这个分组。程序坞只保存一个引用，文件不会被移动、复制或新建。不是程序的真实文件（文件夹不会被打开）拖到栏上时，会点亮注册了它们全部类型的应用；把文件拖到其中一个应用上，文件就用它打开，对于程序坞能跟踪运行状态的应用，它还会进入打开中的状态（2.3）；拖到其他地方则什么都不做。拖到分组上时，它的分组面板会在 500 ms 后打开，好让其中一个成员接住文件；把文件拖到已打开的分组面板的成员上，文件就用这个成员打开。「添加应用…」打开 Windows 的应用文件夹，方便从那里拖入。「添加任务栏上的应用」会加入任务栏上固定、但程序坞里还没有的应用，顺序与任务栏一致，并且不会改动任务栏。
- **程序坞，菜单**：右键应用，有「打开」「以管理员身份运行」（商店应用没有这一项）「打开文件所在的位置」「从程序坞中移除」和「显示更多选项」（Windows 自己的菜单，和大文件夹一样）。分组面板里的成员用同样的应用菜单。右键分组，有「全部打开」「重命名」「取消分组」和「移除分组」，移除前会先询问；它的程序不会被删除，只是不再显示在栏上。右键栏，有「添加应用…」「添加任务栏上的应用」「图标大小」（小、中、大）和「移除程序坞」，移除前会先询问。删除只能通过这些菜单：把应用拖出栏不会删除它。
- **程序坞，分组面板**：点击面板里的成员，会启动它或把它的窗口拿到前面，并关闭面板；按 Esc 或点击面板以外的任何地方，也会关闭面板。在面板里拖动会调整成员的顺序；把成员拖出面板并放到栏上，它就会离开分组。右键成员，有应用菜单。重命名时，Enter 保存新名称，Esc 取消。「全部打开」是面板上的按钮，也是分组菜单的第一项。
- **必须**：纯装饰层设置 `IsHitTestVisible = false`。
- **必须**（不透明主题）：正文文字和背景的对比度 ≥ 4.5:1，大数字 ≥ 3:1。只用于刻度、分隔线的弱色（像素主题的 `Faint`）不能用来写正文。
- 毛玻璃的背景是实时的，无法保证对比度，见 4.1 的「已知取舍」。

### 2.8 性能

- **必须**：空闲时几乎不占 CPU。只在数据变化或时钟跳动（对齐到整秒或整分）时重绘；不写每帧都刷新的循环；过渡动画不超过 1 秒。
- **必须**（程序坞）：窗口跟踪只靠窗口事件，从不用定时器；程序坞隐藏时不占用任何资源。程序坞的每个动效都不超过 1 秒。正在打开的应用会停住不动（不循环），直到它的第一个窗口出现。
- **必须**（动效，2026-10-22 新增），两个主题的每个动效都遵守：
  - Windows 的「动画效果」关掉时（`UISettings.AnimationsEnabled`，每个动画开始时读取，不依赖它发通知），一切直接变成最终状态。
  - 输入从不等动画：动画进行中的点击、按键、拖动或放下立即生效，按最终布局算。
  - 新状态打断正在跑的动画，从当前位置接着走。
  - 静止后什么都不跑：不留着挂上的 `CompositionTarget.Rendering`，也不留着在跑的计时器。所有动效共用一个计时器（`Motion/FrameClock.cs`），只为下一个到点的动画重新定时，没有动画时就停。
- **已知的取舍**（2026-10-22）：每个 WinUI 窗口创建再关闭，都会留下约 2.6 个内核句柄（一个空窗口测出来一样），所以手动添加再移除一个小组件要多 3 到 4 个句柄。小组件都是手动、很少添加的，所以不复用窗口；其余的泄漏（关闭后的窗口上还挂着的事件处理、每个实例一个的计时器、没释放的 Composition 对象）已经修好。
- **应该**：重用画布、位图和画刷，不要每次重绘都分配大对象。

### 2.9 代码分层

- **必须**：数据和文案放在共享层（`DeviceStatus`、`WorldCities`、`Strings`……），主题层只负责「画」。同一条信息在各主题里的写法由同一个共享函数产生（例：`WorldCities.FormatTime` / `FormatDate` / `DescribeOffset`），主题只能在放不下时做 2.5 里那种有记录的压缩。
- **必须**：每个主题的画法放在自己的文件里。毛玻璃 = 组件类里的 XAML 和代码；像素 = `Pixel/` 基础设施 + `Widgets/<组件>/<组件>PixelScene.cs`。新主题照此新建 `<主题名>/` 文件夹和 `<组件><主题名>Scene.cs`。
- **必须**：组件只用本主题调色板里的颜色角色（第 8 节），不在组件里写死色值。
- **应该**：没有专属画法的组件也能工作（它的 XAML 内容会直接放在当前主题的卡片上）。但正式发布的主题应该给每个组件都做专属画法。

### 2.10 素材来源

- **必须**：字体、图标、精灵图必须是原创、系统自带，或者许可允许再分发。不打包 Apple 的 SF 字体，也不从游戏截图里抠素材。现有主题用了系统字体（Segoe UI Variable、Segoe Fluent Icons、宋体）、手绘的像素字体和精灵图，以及一种打包的字体：给大文件夹中文用的 **Fusion Pixel Font 8px**（简体中文、比例字体，2026.10.16 版，作者 TakWolf，SIL Open Font License 1.1）。它的许可文本随 exe 一起发布（`OFL-FusionPixel.txt`），压缩后的字表由 `tools/Make-FusionFont.ps1` 生成，字体只按原样使用。表情不打包：运行时通过 Win2D（`Microsoft.Graphics.Win2D`，MIT）渲染系统的 Segoe UI Emoji，再缩到像素主题的调色板上。

### 2.11 程序坞：显示与隐藏

程序坞是唯一位于窗口之上的小组件。它不是小组件类型，也没有卡片；其他小组件都留在桌面层。

- **必须**：程序坞始终置顶，但从不抢焦点。点击它之后，原来在前面的窗口仍然在前面。
- **必须**：所在屏幕上没有窗口最大化时显示，在桌面和普通窗口上方都显示。
- **必须**：所在屏幕上有窗口最大化时隐藏，向下滑出底边。最小化的窗口、位于其他虚拟桌面上的窗口和工具窗口不算在内。没有最大化的大窗口不会触发隐藏，它仍然在程序坞下面。
- **必须**：全屏窗口（游戏、视频、幻灯片放映）在前时也隐藏。窗口要同时满足两个条件才算全屏：覆盖整个显示器，并且系统报告忙碌状态（`SHQueryUserNotificationState`，即全屏 Direct3D 或演示模式）。两个条件必须同时成立，只看系统状态不够。全屏窗口在前时，底边不会把程序坞唤出来。
- **应该**：全屏判断不明确时，就隐藏。程序坞偶尔多隐藏一次，比它盖在游戏上面要好。
- **必须**：鼠标移到程序坞正下方的底边，或移到它两侧各约一个槽位（一个图标加上它的间距）的底边，或文件拖动到这段底边时，程序坞向上滑出。边缘触发区只覆盖这一段，不是整条底边。鼠标离开程序坞和触发区 600 ms 后，程序坞向下滑走，两个主题相同；鼠标停在其中任何一处时，它不滑走。菜单、分组面板或拖动正在进行时，也不滑走。在最大化窗口上方打开程序坞时，它一开始是隐藏的。滑走之后，它的窗口是隐藏的，而不是停放在屏幕底边下方。
- **必须**：不占用空间。最大化的窗口仍然占满整个屏幕，所以程序坞要为它们让开。

## 4. 各主题规格

### 4.1 毛玻璃 Glass

用户已确认（2026-10-12）：

- **薄、通透**：DWM host backdrop 实时模糊窗口背后的内容，上面只叠 24% 的底色（浅色模式白、深色模式黑）和一道斜向高光。
- **不加描边**（用户觉得卡片四周的白线难看），**不加阴影**（XAML 阴影会盖在系统层的玻璃上面，把它弄脏）。
- **不要用加厚底色来提高对比度**（「太厚」的版本被用户否决过）。
- 圆角 22 DIP，抗锯齿。

字号（现有取值，新组件就近选用）：

| 用途 | 字体 | 字号 / 字重 |
|---|---|---|
| 主角大数字（时钟时间、单设备电量） | Segoe UI Variable Display | 36–64，SemiBold |
| 列表大数字（世界时钟时间、列表电量） | Display | 17–28，SemiBold |
| 列表标题（设备名、城市名） | Segoe UI Variable Text | 14–15，SemiBold |
| 正文（名称、时间、中号电量） | Text | 11–15 |
| 辅助信息（日期、状态、时差） | Text | 11–12，次要色 |

**已知取舍**：玻璃很薄，所以在很暗的壁纸上，浅色模式的深色文字对比度会下降（反过来也一样）。从 2026-10-27 起，所有文字都是实色：浅色模式纯黑，深色模式纯白（只有不在场的东西还是淡色，见第 8 节的 Inactive），这是 24% 底色下能做到的最大对比：在用户的深蓝壁纸上，世界时钟的时间和日期从约 1.5:1 提高到约 3.5:1。进一步的改进方向（尚未实现）：根据卡片背后的亮度自动选文字颜色，而不是加厚底色。

**大号卡片**（344 × 364，2026-10-22）：新增的 20 DIP 只用于行距和留白，不加内容，不改字号。电池：上下内边距 16，行距 8，六行 48 高的行结束在 y 344。世界时钟：内边距 14，四行各 84，表盘 60（带数字，和中号一样；56 时只有刻度）。大文件夹：行高 80，四行从 y 34 起结束在 354。

**大文件夹**（2026-10-21 新增；尺寸单位 DIP）：

- **卡片：** 照常的毛玻璃卡片。标题在 y 12 到 30：文件夹名（Text 13 SemiBold，中间省略）、数量（Text 12，次要色）和一个箭头。格子：小 2×2（列宽 70，行高 60，图块 40），中 4×2（列宽 80，行高 60，图块 40），大 4×4（列宽 80，行高 80，图块 44，在行 + 4）。名称用 Text 10、行高 13（大号 10.5）：小号一行宽 68，中号一行宽 78，大号两行宽 78；名称框从行 + 46 开始（大号行 + 52）。堆叠的小图块是 16（大号 17）。（第 8 阶段，2026-10-21：此前名称是 Text 11 和 12，一行，宽 64 和 74。）
- **图标：** 每一项都放在圆角图块上（圆角 0.225 × 图块尺寸），带一层淡淡的光泽。14 种文件类型和第一批 13 个应用是我们自己画的（一种颜色加一个图案，绝不用 logo；路径数据在设计稿的 `ICONS.md` 里，经 `SvgPath` 绘制）。其他应用把它真实的图标放在 `Tile plate` 底板上，占图块的 0.68；图标本身已经铺满方形时则铺满图块。图片和视频显示真实缩略图并裁成图块形状（视频加播放标记）。仅在云端的文件绝不下载：在有缓存缩略图之前一直显示类型图块。
- **状态：** 悬停和按下的底板（`Hover`、`Pressed`）淡入 100 ms、淡出 150 ms；目标已经不存在的应用不透明度 40%，名称用次要色；空文件夹显示带下载图形的圆盘；找不到文件夹显示警告图形，每个尺寸都显示路径，中、大号再加提示「右键 › 选择文件夹…」；拖入时整张卡片罩上一层 `Drop tint`，并显示一个带动作的 `Select` 胶囊。
- **面板：** 440 × 500 的玻璃窗口，在卡片旁 12 DIP（放得下并留 8 的余量就放右边，否则放左边；会超出底部就上移）。它按 2.3 的规则关闭。标题和数量、排序按钮、搜索框、五列 80 × 92 的格子（名称两行，Text 11、行高 14，在 76 × 28 的框里），底部是路径和「已选择 n 项」。选中是 Finder 风格：图块下一块 `Pressed` 底板，每行名称下一个 `Select` 胶囊；键盘焦点是 2 DIP 的 `Select` 环。重命名是在名称位置上的一行文本框。
- **菜单：** 经 `MenuFlyout` 显示 `MenuEntry` 行，与其他组件一样。项目菜单以「显示更多选项」结尾（字形 E712），它会打开 Windows 自己的菜单（2.3）。
- **动效**（第 12 阶段，2026-10-22；都已做：大文件夹的 A1 到 A4，然后是电量 B6、尺寸和主题切换 B7、添加或移除小组件 B8；菜单和消息框 B5 保持 WinUI 和系统自己的动效）。规则见 2.8。词汇：Quick 100 ms（Out）、Exit 150 ms（In）、Enter 240 ms（Out）、Move 280 ms（Move）、Press 80 ms 和 Release 200 ms（磁贴缩到 94% 再回来）、Blend 250 ms（底色和高光）、Ring 700 ms（电量环，不变）。Out = 三次贝塞尔 (0.2, 0.8, 0.2, 1)，In = (0.4, 0, 1, 1)，Move = (0.3, 0, 0.1, 1)。整窗口的淡入淡出用分层窗口 alpha，毛玻璃和 XAML 就保持同步；否则毛玻璃和 XAML（两个合成器）会差约一帧。
  - **面板（A1）：** 打开时窗口淡入（Enter），同时毛玻璃和卡片从卡片一侧向外移 8 DIP，并以靠卡片一侧的角为中心从 97% 放大；关闭时淡出、向卡片方向退回 6 DIP、缩到 98%（Exit），消失后才隐藏窗口。窗口从第一帧起就在最终位置和大小，淡出时不接收点击。关闭过程中再打开，就从当前 alpha 接着走。
  - **项目（A2、A4），卡片和面板都一样：** 每个项目只有一个单元格，以文件名为键（改名保留单元格）。新项目的单元格进入（不透明度和以磁贴为中心的 85% 缩放，Enter）；项目换了位置的单元格滑到新位置（Move）；项目离开的单元格在原地变到不透明度 0 和 85%（Exit）后移除；它们同时开始，进入的单元格比离开的晚 80 ms。只有在视野内的单元格有动画。把项目从面板拖出去时，被拖的单元格在拖动期间降到 40%（Quick）；移动完成后它们离开。
  - **拖到卡片上（A2）：** 放置底色淡入（Quick），标签淡入并从下方 6 DIP 升起（Enter）；修饰键改变动作时，文字立即替换；离开或放下时两者都淡出（Exit）。
  - **悬停和按下（A3）：** 底板（单元格、标题、堆叠、面板的排序按钮）淡入（Quick）、淡出（Exit）；按下时磁贴缩到 94%（Press），松开、移开或按下变成拖动时回弹（Release），这就是一次点击的确认；搜索框背景在 `Hover` 和 `Pressed` 之间用 120 ms 过渡。「无匹配」淡入（Enter）、淡出（Exit）。
  - **电量（B6）：** 电量环滑到新电量用 Ring，数字立刻变（不变）；充电闪电（百分比那一行里的，和电量环上的角标）在开始充电时淡入（Quick）、停止充电时淡出（Exit）。
  - **尺寸变化（B7）：** 旧内容淡出（Quick）；窗口取两个尺寸的并集，毛玻璃的裁剪区和卡片上配套的圆角裁剪区从旧矩形移到新矩形，以左上角为锚点（Move）；旧内容消失后，新内容按自己的尺寸排版，在 Move 过半时淡入（Enter）；然后窗口收到新尺寸。再来一次尺寸变化，先把正在跑的这次做完。
  - **主题（B7）：** 浅色变深色时底色和高光渐变（`BrushTransition`，Blend），文字、磁贴和底板立刻变。像素变毛玻璃：旧卡片立刻消失，新卡片淡入（Enter，分层窗口 alpha，不缩放）。毛玻璃变像素用像素的（4.2）。
  - **添加或移除小组件（B8）：** 卡片淡入并以中心为基准从 96% 放大（Enter；用分层窗口 alpha，毛玻璃、底色和内容一起动）；移除时变到不透明度 0 和 96%（Exit），然后关闭窗口。正在离开的卡片不接收点击。

**程序坞**（2026-10-31 新增；尺寸单位 DIP；详细来源是 `notes/design/glass/dock-20261031/HANDOFF.md`）：

| | 小 | 中 | 大 |
|---|---|---|---|
| 图标 | 40 | 48 | 64 |
| 内边距（上、下、两端） | 12 | 12 | 12 |
| 图标间距 | 12 | 12 | 12 |
| 栏高 | 64 | 72 | 88 |
| 圆角 | 20 | 22 | 28 |
| 悬停上浮 | 4 | 5 | 6 |
| 分组小图（内缩，间距） | 15（4，2） | 18（5，2） | 24（6，4） |
| 空栏长度 | 240 | 280 | 340 |

- **长度**：2 × 内边距 + n × 图标 + (n − 1) × 间距，n 是应用数量。像素主题用同样的几何（4.2）。
- **窗口**：栏本身，上方另加 42 DIP 的透明空间，用来放名称标签。空间里的点击穿透到后面的窗口。栏的底边离屏幕底边 8 DIP。
- **毛玻璃**：栏使用卡片的玻璃（DWM host backdrop 模糊、24% 底色和斜向高光），圆角如上表。任何状态都没有描边，也没有阴影。用户决定：栏在窗口之上也保持这层薄玻璃；在白色或黑色窗口上，栏几乎看不见，图标像是浮着的。这是接受的结果，不要加厚底色。
- **图标**：自定义应用和文件类型用大文件夹的图块美术（设计稿里的 `ICONS.md`）。真实图标放在 `Tile plate` 底板上，占图块的 0.68；图标本身已经铺满方形时，就铺满整个图块。图块圆角为图标尺寸的 0.225 倍。
- **分组图标**：一块与图块同尺寸的 `Hover` 底板（圆角为图标尺寸的 0.225 倍），上面是前四个成员的小图，排成 2 × 2（尺寸见上表），小图上没有文字。运行中的成员，其小图显示它的运行图标；分组本身没有运行图标。
- **名称标签**：高 26 DIP 的药丸形标签，底边离栏顶边 8 DIP，以图标为中心，离屏幕边缘至少 8 DIP。宽度是文字加 20 DIP，最宽 240 DIP；更长的名称由 `NameShortener` 从中间缩短。
- **空状态**：下载图标（`E896`，16 DIP）和「把应用拖到这里」（Text 12，Primary），在栏中居中。
- **分组面板**：自己的窗口，浮在程序坞上方，以分组图标为中心，并保持在屏幕之内。宽度为 20 + 列数 × 80 + 20 DIP，列数为 clamp(数量, 3, 4)，即 3 列 280 DIP、4 列 360 DIP；最多显示三行 80 × 92 的格子，超出的部分滚动。标题行是分组的名称（可以就地改名，Enter 保存，Esc 取消），右侧是「全部打开」按钮。每个格子是 48 DIP 的图块，名称最多两行（Text 11）；运行中的成员显示运行图标；悬停和按下的底板与大文件夹的相同。它的操作见 2.7。
- **状态**：
  - 空闲：图标。
  - 悬停：图标上浮，标签显示名称（分组则显示分组的名称）。
  - 按下：图块以中心为基准缩到 94%。
  - 缺失：图块不透明度 40%，标签显示「找不到 {name}」。缺失的应用靠不透明度变暗，不用 `Inactive` 角色。点击会打开一个小菜单：一行禁用的「{name} 找不到」标题，然后是「从程序坞中移除」。
  - 添加（有程序被拖到栏上）：在它将落下的位置，打开一个图块大小、用 `Hover` 填充的空位（圆角 0.225）。后面的图标滑开，栏长增加一个图标加一个间距。
  - 运行中、打开中、关闭中：运行图标交换图块的明暗和颜色（有色的自定义图标图块变白，白色的变有色），没有小圆点，也没有描边和阴影。13 个自定义应用使用设计交接文档里的配色表。没有自己图标的通用应用图块按同样的规则交换。
    - **真实图标**保留它的图片，占图块的 0.68，放在强调色底板上，而不是白色的 Tile plate。底板每张图片只算一次，然后缓存：
      - 色相是图标里不透明（alpha ≥ 200）且有饱和度（HSL 饱和度 ≥ 0.35）的像素的色相，按饱和度加权取平均；
      - 饱和度取这些像素的平均饱和度和 0.55 中较大的那个；明度浅色栏为 0.38，深色栏为 0.42；
      - 白色、灰色或大部分透明的图标（不透明像素里有饱和度的不到 2%）用中性底板 `#3A3A3C`。

  - **面板：** `PixelPopupWindow` 里 220 × 196 个美术像素（圆角台阶 [4, 2, 1, 1]，带对话框那样的硬阴影），离卡片 4 个美术像素（放得下放右边，否则左边，再不行盖在卡片上）。一行是文件夹名和「n 项」；一行是搜索框（凹槽、放大镜、1px 光标）和排序按钮（文字和箭头）；然后是五列格子（横向间距 41，纵向 33，Fusion 度量时 39，宋体度量时 45），名称两行用 `PixelFonts.Small`，3px 滚动条，点线，底部（路径用 `Soft`，「已选择 n 项」用 `Ink`）。选中的格子是 `Select` 底板加 `OnSelect` 文字；键盘焦点是点线环；滚轮每格滚一行。
  - **行为：** 与毛玻璃相同（2.3）。随处打字就是搜索（Backspace 删一个字符）；输入框通过系统的文本服务接收文字，所以拼音输入法（候选框开在输入框旁边）、表情面板和 Ctrl+V 都能用，表情在名字里保持完整；F2 就地重命名，输入框出现在格子或标题行里；Delete 把选中项送进回收站；F4 或 Alt+↓ 打开排序列表。Esc 先取消重命名，再清空搜索，最后关闭面板。面板按 2.3 的规则关闭：它自己的菜单、对话框和文件操作窗口出现时不关，别的程序拿到前台时才关。选中的项目经 OLE 拖出，资源管理器和桌面接受它的方式与接受资源管理器自己的拖动相同。
  - **键盘与 Narrator：** 面板是一个窗口，里面有搜索框（Edit，带 Value 模式）、排序按钮（ExpandCollapse）和每个显示的项目一个列表项（Invoke 和 SelectionItem）。
  - **菜单：** 项目菜单和组件自己的菜单行用上面说的像素菜单。项目菜单以「显示更多选项」结尾，前面有一条分隔线，没有图标（和打开、属性一样）；它会打开 Windows 自己的右键菜单，在像素主题下仍是系统的样子（2.3）。
  - **动效（A1 到 A4）：** 面板从靠卡片的一侧、以完整高度 GROW（宽度 1/3、2/3，然后是面板；120 ms），窗口一开始就是最终大小，其余部分透明；SHRINK 时缩回那一侧（2/3、1/3；80 ms）；从第一刻起就算已关闭。拖到卡片上时，先显示 16 个点取 1 个的稀疏底色、没有标签，再显示原来的底色（4 个点取 1 个）加标签；离开时反过来，放下时直接去掉。列表变化（放下、重新扫描、排序、搜索）时：留在原行的单元格 MOVE，新的和换了行的 POP，旧的 LEAVE（3 帧，120 ms，只对视野内的单元格）。悬停时单元格内容上移 1 px，配 `Open fill` 底板（标题也一样）；按下时下移 1 px，配 `Shade`；完成一次点击时底板用 `Select` FLASH 一下；被拖出面板的单元格在拖动期间只画一半像素。

**程序坞**（2026-10-31 新增；所有数字都是美术像素；详细来源是 `notes/design/pixel/dock-20261031/HANDOFF.md`）：

| | 小 | 中 | 大 |
|---|---|---|---|
| 图标 | 20 | 24 | 32 |
| 槽位（图标加每边 2 的光晕空间） | 24 | 28 | 36 |
| 栏高（2 × 内边距 4 + 槽位） | 32（64 DIP） | 36（72 DIP） | 44（88 DIP） |
| 分组小图（尺寸，间距） | 7（1） | 9（1） | 12（2） |

- **间距**：从卡片边框到槽位是 4，加上 2 的光晕空间，所以边框到图标是 6（12 DIP）。槽位之间是 2，所以图标之间是 6（12 DIP），两个光晕不会互相碰到。长度 = 2 × 4 + n × 槽位 + (n − 1) × 2。空栏长 120、140 或 170 个美术像素（240、280 或 340 DIP）。每个尺寸的内边距和间距都与毛玻璃相同（4.1）。
- **窗口**：栏底边离屏幕底边 4 个美术像素（8 DIP）。栏上方有 21 个美术像素（42 DIP）的透明空间放名称标签；窗口宽度要能放下两端最宽的标签。
- **图标**：每个尺寸在自己的网格上绘制，不缩放。自定义应用和文件类型用第 8 节的精灵角色。图块有 1 px 墨色描边、填充色、底边一道阴影唇，以及从顶部开始的台阶角：20 时为 [3, 2, 1]，24 时为 [4, 2, 1, 1]，32 时为 [5, 3, 2, 1, 1]。真实图标在程序坞的尺寸下使用大文件夹的第二层规则。
- **分组图块**：应用图块的外形，用银色（`g`，阴影 `s`），里面是最多四个小图排成的 2 × 2。每个小图是应用的 32 个美术像素图标（运行中为醒着的画法），在小、中、大时缩到 7、9、12 个美术像素，小图之间的间距见上表。2 × 2 在图块中居中。
- **边框和阴影**：卡片的边框（描边、Panel 填充、顶部 1 px 的 Highlight 行、底部两行 Shade，以及台阶角 [4, 2, 1, 1]），右下方有菜单那样的 2 px 硬阴影 Shadow。程序坞是唯一带阴影的卡片，因为它浮在窗口之上；桌面上的卡片仍然没有阴影。
- **光晕**：运行中的图标有一圈 1 px 的光晕，沿图标形状，比图标外 2 个美术像素。光晕的颜色是自定义应用精灵自己的颜色；通用图块用石板色（`s`）；其他情况取真实图标中最常见的有颜色的精灵角色像素（墨、白、银、石板和暮色不计；都没有时用蓝色）。之后光晕要在栏上保持清晰：浅色栏上，黄色降一级到橙色，青和青柠各降两级（到蓝和青绿）；深色栏上，紫、藏青、青绿和暮色各升一级。光晕使用精灵角色；程序坞不增加颜色角色。
- **状态**：
  - 空闲：空闲图案。
  - 悬停：图标在每个尺寸下上浮 2 个美术像素（4 DIP），并显示名称标签。点击区域留在槽位上，上浮只移动图案。
  - 按下：槽位后面一块 `Shade` 底板（角为 [2, 1]），图标下移 1 px。
  - 缺失：墨色变成 `Faint`，其他颜色变成 `Track`，和大文件夹一样。点击会打开像素风格的问题对话框：「找不到“{app}”。要把它从程序坞移除吗？」，带「移除」（主按钮，有焦点）和「取消」。
  - 添加：在将落下的位置，打开一个点线框，宽度为一个槽位加一个间距（`Soft`）；后面的图标向后移动一个槽位。
  - 调整顺序：被拖的图标跟着指针走，上移 6 px，不变暗。原来的槽位是 `Faint` 的点线框，直到其他图标移开。
  - 空状态：一个 `Faint` 的点线框，离光晕空间留有内缩，中间是 `Soft` 的「把应用拖到这里」（像素字体显示为大写 DROP APPS HERE）。
  - 运行中、打开中、关闭中：醒着的图案和光晕，配合下面动效里的跳动和溶解。真实图标和通用图块只保留它们唯一的图案，并加上光晕。
  - **组成分组**：一个程序在另一个图标上停留 500 ms 后，目标立即变成带有自己小图的分组图块，被拖的图标浮在它的上面。松手时，被拖应用的槽位收拢，分组图块呈现 2 × 2 的小图。
  - **用应用打开**：能打开这些文件的应用立刻显示 `Select` 底板。指针下的那个还会上移 2 px，并把名称标签显示为「用 {name} 打开」（`Select` 底板，`OnSelect` 文字）。拖到分组上时，500 ms 后打开它的分组面板。
- **名称标签**：菜单风格的标签（描边、Panel 填充、1 px 的 Highlight、一行 Shade、台阶角 [2, 1]，以及 2 px 硬阴影）。像素字体的文字，标签高 13 个美术像素；Fusion 字体，高 15 个（26 或 30 DIP）。文字离左右各 5 px。标签底边在栏顶边上方 4 个美术像素，以图标为中心，离屏幕边缘至少 4 px。宽度最多 120 个美术像素（240 DIP）；更长的名称由 `NameShortener` 从中间缩短。
- **字体**：名称标签、空状态文字和程序坞的其他文字，沿用上面大文件夹的 Fusion 规则：整段文字像素字体（`PixelFonts.Regular`，5×7）能拼出就用它；否则 Fusion Pixel 8px 能覆盖全部就用它；否则整段用宋体 12px 点阵。这条规则扩展到程序坞的标签和空状态文字。菜单和对话框仍用宋体。
- **分组面板**：一个弹出窗口，外框和对话框一样（台阶角 [4, 2, 1, 1]，带硬阴影），以分组图标为中心，保持在屏幕之内 4 个美术像素。它的底边在栏顶边上方 6 个美术像素，间隙里有一个 4 行的台阶小箭头指向图标。格子为 40 × 46 个美术像素，两边各留 10 像素的内边距，所以列数为 clamp(数量, 3, 4)，面板宽 140（3 列）或 180（4 列）个美术像素；最多显示三行，超出的部分滚动，滚动条宽 3 像素。标题行是分组的名称，右侧是「全部打开」按钮。每个成员是 24 像素的图标（运行时有光晕），下面是最多两行的名称；悬停用 `OpenFill` 底板。它的操作见 2.7。
- **菜单**：本节的像素菜单，文字按 2.7。「显示更多选项」和大文件夹一样没有图标，它打开 Windows 自己的菜单。
- **动效**：步进帧，T = 40 ms，整数美术像素，不用透明度。动效时刻与毛玻璃（4.1）的 D1 到 D15 相同，画法如下：
  - **D1 悬停**：先上移 1 px，再上移 2 px（2 帧）；第二帧时出现标签底板。离开时下移 1 px（1 帧），标签底板立刻消失。
  - **D2 按下**：`Shade` 底板，图标下移 1 px。松开时，`Select` 的 FLASH 一帧，应用立刻启动。
  - **D3 打开**：HOP（图标依次上移 1、2、3、3、2、1、0 个美术像素，共 280 ms），然后 DISSOLVE 第 1、2 帧变成醒着的图案。它会停住（不循环），直到第一个窗口出现。
  - **D4 已打开**：DISSOLVE 第 3、4 帧。在别处启动的应用，四帧都从空闲开始。没有弹跳。
  - **D5 关闭**：从醒着的图案 DISSOLVE 回空闲（4 帧，160 ms）。超时（10 秒内没有窗口）时，从停住的状态 DISSOLVE 回空闲，两帧。
  - **D6 隐藏和显示**：STEP。窗口每个像素帧（40 ms）移动一次，移到毛玻璃 D6（4.1）的滑动在那时所在的位置，所以栏是一步一步地动，向上滑出和落回都是如此。画面只画一次，每一步只移动窗口。鼠标离开 600 ms 后滑走，和毛玻璃一样。滑走之后，窗口是隐藏的，而不是停放在屏幕底边下方。
  - **D7 调整顺序**：被拖的图标随指针上移 6 px。指针越过下一个槽位的中线时，那个图标以 MOVE（3 帧）移过去，空位跟着移动。放下时立即完成。
  - **D8 组成分组**：长按计时器触发时，目标立即变成带有自己小图的分组图块。松手时，被拖应用的槽位收拢（MOVE），分组图块 POP（先上移 1 px，然后归位）。
  - **D9 分组面板**：从栏向上以完整宽度 GROW（高度 1/3、2/3，然后全部；120 ms）；收回时 SHRINK（2/3、1/3；80 ms）。
  - **D10 添加**：拖动经过时，指针后面的图标 MOVE 让出一个槽位（3 帧），栏随之变长；放下时新图标 POP 进入。
  - **D11 移除**：LEAVE（Bayer ≥ 8，再 ≥ 12，然后消失）；然后后面的图标 MOVE 补上（3 帧），栏变短。
  - **D12 用应用打开**：高亮的底板立刻显示；目标上移 2 px，带着 `Select` 底板和标签。放下时全部立刻消失，然后程序坞能跟踪的应用开始 D3。拖到分组上时，500 ms 后打开它的分组面板（D9）。
  - **D13 图标尺寸**：窗口立刻取新尺寸，栏的边框立刻画好，图标 DISSOLVE 进来（4 帧）。
  - **D14 缺失**：没有动效，直接变化。
  - **D15 浅色深色、毛玻璃与像素切换**：浅色深色切换时整个程序坞 DISSOLVE；毛玻璃变像素时，边框立刻画好，图标 DISSOLVE 进来。
  - 沿底边滑动栏时，栏跟着指针走，没有自己的动效。2.8 的规则同样适用：关闭「动画效果」时一切直接到位；输入从不等待；新状态打断旧动效；没有循环。

## 5. 新增一个主题

1. **先设计**：按附录 A 填写设计简报，写进第 4 节。做出静态预览（每个组件 × 每个尺寸 × 浅/深 × 中/英），给用户确认后再写代码。
2. **写代码**：
   - 在 `WidgetTheme` 枚举末尾加值。名字会以文本形式存进 `settings.json`，定了就不能改名。
   - 在 `Strings.ThemeName` 里加中英文名称。托盘菜单和右键菜单会自动列出新主题。
   - 卡片：改 `WidgetFrame.SetCard`。需要实时模糊才调用 `GlassBackdrop.SetVisible(true)`。如果卡片的像素尺寸不是「DIP × 缩放」，同时修改 `WidgetLayout.GetCardPixels`。
   - 调色板：新建一个类，第 8 节的角色要齐全，浅、深两套。
   - 每个组件：在构造函数里按 `context.Theme` 选择画法，覆盖它支持的全部尺寸。
   - 预览：仿照 `Pixel/PixelPreview.cs`，让新主题也能一条命令导出全部布局的总览图。
3. **写文档**：更新 README 的简介和操作表、本文件第 4 节，以及文末的变更记录。
4. **验收**：第 7 节全部通过。

## 6. 修改现有主题

### 6.1 改动分级

| 级别 | 例子 | 要求 |
|---|---|---|
| 微调 | 间距 ±1–2、同一角色内换色、措辞 | 跑第 7 节的相关检查，写变更记录 |
| 主题内改版 | 某个尺寸换布局、换图标或字体、调整动效 | 给用户看改动前后的对比图；更新第 4 节 |
| 共享规则变更 | 卡片尺寸、显示哪些信息、颜色含义、交互方式、文案、设置字段 | 先问用户；所有主题在同一次改动里一起改；更新第 2 节 |
| 推翻用户决定 | 例如给毛玻璃加描边或阴影、把城市名改回中文 | 必须先得到用户明确同意 |

### 6.2 其他规则

- **兼容**：已经存进 `settings.json` 的标识不改名、不删除：
  - `TypeId`：battery、clock、worldclock、folder
  - 枚举名：`WidgetTheme`、`WidgetSize`、`AppLanguage`
  - 选项键：showNames、showDisconnected、cities、showSeconds；大文件夹的是 `path`、`sort`（newest、name、type 或 manual）和 `order`（文件名的 JSON 数组，手动排序用）
  - 顶层设置 `FolderRoot`（可选的文本，新建大文件夹所在的文件夹；没有它就用默认位置）

  新增选项的默认值必须保持原有行为。
- **多人协作**：可能有好几个会话同时在改这个仓库。
  - 改文件前重新读一遍。
  - 保持每个文件原有的换行符（仓库里 CRLF 和 LF 混用）。
  - 不顺手格式化没改动的代码，不回退别人的改动。
- **留证据**：每次视觉改动都附上截图或预览图。
- **记录**：在文末「变更记录」写一行：日期、主题、改了什么、为什么。

## 7. 验收清单

**构建**

- [ ] `dotnet build src/DeskWidgets.App -c Release` 零错误、零警告。（运行中的 Debug 程序会锁住 exe，用 Release 检查编译。）

**画面**：每个组件 × 每个支持的尺寸

- [ ] English 和中文都检查。
- [ ] 系统浅色和深色都检查。深色用预览图检查，**不要为了测试去改用户的系统设置**；需要在真机上看，就请用户自己切换。
- [ ] 极端数据：
  - 长名称：Los Angeles、Mexico City、需要换两行的设备名
  - 中文回退字体
  - 电量 ≤ 20%、充电中、未连接、没有设备
  - 已经跨到第二天的城市、白天和夜间表盘
- [ ] 缩放：至少检查 100% 和 150%。像素主题要确认没有发虚、或宽窄不一的像素。

**行为**

- [ ] 从托盘菜单和右键菜单切换主题，都不用重启；切换后位置重新吸附；没有上一个主题的残留层（例如像素主题下看不到模糊玻璃）。
- [ ] 切换语言实时生效。
- [ ] 拖动和右键菜单正常。
- [ ] 空闲时 CPU 接近 0。

**怎么检查**

- 像素主题：`DeskWidgets.exe --pixel-preview <新文件夹>` 导出昼/夜 × 中/英四张总览图。程序运行中也能用。
- 像素主题的大文件夹：`DeskWidgets.exe --pixel-folder-preview <新文件夹>` 导出它的总览图（各个尺寸的卡片、状态、图标和面板；昼/夜 × 中/英）。程序运行中也能用。
- 测试布局：
  1. 先备份 `%LOCALAPPDATA%\DeskWidgets\settings.json`。
  2. 用「置顶」的测试布局启动并截图。
  3. 测完恢复用户原来的设置，重新启动程序。
- 截取桌面上真实的组件：小组件常被别的窗口挡住，普通截屏拍不到。用开启 Per-Monitor V2 DPI 感知的进程调用 `PrintWindow(hwnd, PW_RENDERFULLCONTENT)`。注意：这样截不到毛玻璃的模糊效果。

## 8. 颜色角色对照

| 角色 | 用途 | 毛玻璃（浅 / 深） | 像素（浅 / 深） |
